> QR 코드를 촬영해 헬스장 입·퇴실을 기록하고, 운동 기록을 바탕으로 정보와 콘텐츠를 제공하는 서비스다. 퇴실할 때 남기는 오운완 기록으로 꾸준히 운동할 동기도 만들고자 했다.

## 팀 구성

- 김다온 — UI/UX 디자인, 프론트엔드
- 김건호 — JWT 인증 로직, 백엔드
- 김용민 — 백엔드, 데이터베이스

## 서비스 계획

사용자가 QR 코드를 촬영하면 입·퇴실 처리 페이지로 이동한다. 쌓인 기록을 활용해 다양한 자료와 정보를 보여 주고, 퇴실 시에는 그날의 운동을 기록할 수 있도록 구성했다.

주제가 정해진 직후 와이어프레임을 만들고 로그인과 회원가입 이후의 메인 흐름을 설계했다. 당시에는 로그인과 회원가입 화면의 세부 디자인에 많은 시간을 사용했다. 이후 와이어프레임 단계에서는 시각적인 완성도보다 전체 흐름과 정보 배치를 먼저 정하고, 에러 메시지의 위치와 표시 방식 같은 동작을 더 구체적으로 설계해야 한다는 점을 배웠다.

## 기술 구성

- Frontend — HTML, CSS, JavaScript, Tailwind CSS, jQuery, Ajax
- Backend — Python, Flask, Jinja2 SSR
- Authentication — JWT
- Database — MongoDB
- Cloud — AWS EC2

## 회고

### 결과물만 생각했던 순간

짧은 기간 동안 처음 접하는 기술과 프레임워크를 사용해야 해서 개발 자체에 깊이 몰입했다. 거의 완성된 결과물을 만들었지만, 프로젝트의 목표가 결과물만이 아니라 팀워크와 발표까지 포함한다는 사실을 놓쳤다.

### 발표에서 놓친 것

발표에서는 테스트 계정 로그인이 실패해 준비한 시연을 보여 주지 못했고, 정해진 5분도 넘겼다. 개발에 시간을 모두 사용한 탓에 발표 흐름과 예외 상황을 충분히 준비하지 못한 결과였다.

### 팀장으로서 부족했던 점

팀장으로서 경험이 적은 팀원이 뒤처지지 않도록 살피는 일도 부족했다. 미들웨어와 백엔드 코드를 합치는 과정에서 생긴 문제를 내 역할이 아니라는 이유로 깊이 들여다보지 않았다. 팀장은 자신의 코드만이 아니라 팀 전체의 진행 상황과 각 역할이 어떻게 연결되는지를 이해해야 한다는 것을 배웠다.

### 다음 프로젝트에서는

이번 프로젝트는 시험 문제의 의도를 읽지 않고 보이는 문제부터 푼 것과 비슷했다. 다음부터는 구현을 시작하기 전에 프로젝트가 요구하는 목표와 평가 기준을 먼저 확인하고, 개발과 협업, 발표에 사용할 시간을 함께 계획하려 한다.
