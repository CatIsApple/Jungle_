## 알고리즘 대신 프로젝트 구상

오늘은 쉬는 날이다.

알고리즘 문제를 푸는 대신 앞으로 매주 일요일마다 진행할 프로젝트를 구상하기로 했다. 클라우드로 전환하는 것이 목표인 만큼 그 방향과 맞는 프로젝트를 만들고 싶었다.

나는 Go를 좋아하지만 아직 잘하지는 못한다. 그래서 Go를 배우면서 클라우드에 적용할 수 있는 프로젝트를 해보기로 했다.

백엔드 개발자 한 분과 함께 진행하기로 했고, 오늘 회의를 통해 프로젝트의 방향을 구체화했다.

## Gateway와 Go 백엔드

백엔드 개발자분은 Gateway를 FastAPI와 Spring으로 각각 만들어 어떤 차이가 있는지, 성능상 어떤 이점이 있는지 확인해보기로 했다. Spring은 이번에 처음 사용해본다고 했다.

나는 Gateway 다음 영역의 백엔드를 맡아 Go로 기본적인 서비스를 제공할 계획이다.

추가로 Gateway가 HTTP 요청에서 IP 이벤트만 분리해 Go 시스템으로 전달하도록 구성하려고 한다. Go 시스템에서는 goroutine을 활용해 IP 이벤트를 처리하고 IP를 분석한다. 수집한 데이터는 내부 디스크에 저장할 예정이다.

```text
HTTP 요청
   ↓
Gateway · FastAPI / Spring 비교
   ├─ 기본 요청 → Go 서비스 백엔드
   └─ IP 이벤트 → goroutine 처리 → IP 분석 → 내부 디스크 저장
```

이런 프로젝트를 앞으로 진행하기로 오늘 회의에서 구상했다.
